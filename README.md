# 招标截标状态核对

一个面向采购专员的离线可演示网页应用，包含两个入口：

- **招标截标状态核对**：输入项目编号和公告列表网址，判断当前是否仍可投标；
- **保证金退还核对**：输入项目编号、收据编号和保证金明细目录 URL，计算该收据还有多少保证金未退。

招标截标核对会：

1. 从列表页出发，仅跟踪同一站点的分页链接；
2. 抓取与项目编号匹配的公告详情页；
3. 按发布时间串联原公告、更正公告和取消公告；
4. 合并跨页或镜像重复公告；
5. 输出“可投标 / 已截止 / 已取消 / 待核实”，并列明结论依据的标题、发布时间和来源链接。

保证金退还核对详见下文[同名章节](#保证金退还核对)。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：

- 核对应用：<http://localhost:5000>
- 本地分页样本站点：<http://localhost:8080>
- 招标公告样本列表：<http://localhost:8080/notices/page-1.html>
- 保证金明细样本目录：<http://localhost:8080/deposits/page-1.html>

Compose 包含两个服务：

- `web`：Flask + requests + BeautifulSoup 核对应用；
- `sample-site`：使用 Python 静态文件服务器提供的本地分页样本站点。

Web 容器会把浏览器可访问的 `http://localhost:8080` 自动映射为容器网络内的 `http://sample-site:8080`，因此页面中展示的仍然是宿主机可点击的来源链接。

## 样本项目

以样本站点当前虚构数据、系统日期为 2026-11-11 时为例：

| 项目编号 | 演示场景 | 预期结论 |
|---|---|---|
| `GSB-2026-001` | 原公告后两次更正，跨页重复公告被合并 | 可投标，截标时间 2026-11-27 17:00 |
| `GSB-2026-002` | 取消公告后还有普通延期更正 | 已取消，后续更正不恢复招标 |
| `GSB-2026-003` | 同一发布时间两条更正给出不同截标时间 | 待核实 |
| `GSB-2026-004` | 相关更正详情页返回 404 | 待核实 |
| `GSB-2026-005` | 截标时间已过 | 已截止 |

> “可投标/已截止”会随运行时的系统日期变化；样本项目的取消、冲突和详情失败规则不变。

## 保证金退还核对

应用新增“保证金退还核对”入口（<http://localhost:5000/deposits>）。输入**项目编号**、**收据编号**和**保证金明细目录 URL** 后，系统会：

1. 从明细目录页出发，仅跟踪同一站点的分页链接；
2. 读取标注该收据编号的到账、退款和勘误详情，包括流水号、金额、发布时间和勘误引用；
3. 按“类型 + 流水号”去重，跨页或镜像重复记录只计一次；
4. 同一退款流水号存在多条勘误时，按发布时间取最新一条替换该笔退款金额；
5. 汇总各笔退款，输出“未退金额 = 到账金额 − 已退合计”，并逐笔列出来源链接与勘误依据。

以下任一情况会标记为**待核实**，不给出确定余额：

- 同一到账流水号出现金额冲突；
- 同一发布时刻针对同一退款流水号的勘误金额互相冲突；
- 勘误引用的流水号不存在、不是退款记录，或未标注引用/更正金额/发布时间；
- 同一收据的退款合计超过到账金额；
- 相关详情页抓取失败，或关键金额、流水号缺失。

| 收据编号 | 演示场景 | 预期结论 |
|---|---|---|
| `SJ-2026-0007` | 两笔退款，其中一笔被后续勘误更正；跨页有镜像副本 | 尚有未退 18,000.00 元 |
| `SJ-2026-0008` | 同一到账流水号在镜像页金额不同 | 待核实（到账金额冲突） |
| `SJ-2026-0009` | 同一时刻两条勘误给出不同退款金额 | 待核实（勘误冲突） |
| `SJ-2026-0010` | 勘误引用的退款流水号不存在 | 待核实（引用不存在） |
| `SJ-2026-0011` | 到账与退款金额相等 | 已退清 |
| `SJ-2026-0012` | 相关退款详情页返回 404 | 待核实（详情抓取失败） |
| `SJ-2026-0013` | 退款合计超过到账金额 | 待核实（差额异常） |

样本明细目录位于 `sample_site/deposits/`，详情页位于 `sample_site/detail/d-dep-*.html`；`d-dep-refund-0012.html` 故意缺失，用于模拟抓取失败。

### 保证金明细页面结构

- 目录页：`sample_site/deposits/page-1.html` … `page-3.html`
  - 每条明细位于 `.notice-item`（同时带 `data-receipt-no`、`data-project-no`、`data-type`）；
  - 详情链接位于条目的 `h2 a`；
  - 元数据包含 `收据编号：`、`项目编号：`、`流水号：`、`金额：` 和 `<time datetime="...">`；
  - 分页位于 `.pagination`，包含页码和 `rel="next"`。
- 详情页：`sample_site/detail/d-dep-*.html`
  - 标题位于 `h1`，收据编号/项目编号/业务类型/流水号位于 `.publish-meta`；
  - 到账/退款正文使用“到账金额：”“退款金额：”；
  - 勘误正文使用“勘误引用：”“原退款金额：”“更正后退款金额：”。

抓取器同时识别常见表格行结构、`data-*` 属性、中文日期格式和 `meta` 发布时间，不局限于上述固定 class。

## 样本站点页面结构

样本站点模拟常见政府采购公告结构：

- 列表页：`sample_site/notices/page-1.html`、`page-2.html`、`page-3.html`
  - 每条公告位于 `.notice-item`；
  - 详情链接位于条目的 `h2 a`；
  - 项目编号位于 `.project-no` 或 `data-project-no`；
  - 发布时间使用 `<time datetime="...">`；
  - 分页链接位于 `.pagination`，包含页码和 `rel="next"`。
- 详情页：`sample_site/detail/*.html`
  - 标题位于 `h1`；
  - 项目编号、公告类型和发布日期位于 `.publish-meta`；
  - 正文包含“投标截止时间”“延期至”等常见表述。

抓取器并不只依赖这些固定 class：它还会识别常见的 `article/li/tr` 列表结构、分页文字、详情页 `meta` 时间、中文日期格式，以及“响应文件提交截止时间”“开标时间”等标签。

## 判定规则

- **可投标**：未发现取消公告，且按时间链得到的最新截标时间晚于当前时间。
- **已截止**：未发现取消公告，但最新截标时间不晚于当前时间。
- **已取消**：发现取消/终止/废标类公告；其后的普通更正公告只展示在时间链中，不恢复招标。
- **待核实**：
  - 与项目相关的详情页抓取失败；
  - 同一发布时间的更正公告给出互相冲突的截标时间；
  - 分页或详情数量超过安全上限；
  - 缺少关键发布时间或有效截标时间；
  - 未找到与项目编号匹配的公告。

## 本地开发（不使用 Docker）

需要 Python 3.11+。

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt

# 终端 1：启动样本站点
python -m http.server 8080 --directory sample_site

# 终端 2：启动核对应用
python app.py
```

然后访问 <http://localhost:5000>。

## 边界说明

- 仅抓取静态 HTML，不执行 JavaScript；
- 分页跟踪限制在同一站点（同一 scheme、主机和端口）；
- 单个 HTML 页面默认最大 5 MB；
- 详情页请求失败、金额冲突或关键字段缺失时将相关结果标记为“待核实”，不会猜测结论；
- 保证金退还核对只纳入标注目标收据编号的明细；目录分页不完整时结果可能不完整，请留意提示；
- 抓取结果用于辅助核对，正式退款前仍应以采购人或代理机构的书面确认与财务凭证为准。
